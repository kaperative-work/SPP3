# Каталог библиотеки

Учебное приложение: одностраничный каталог книг и REST API. Лабораторная работа №3 добавляет вход по временным ключам, три роли, коды HTTP, защиту от подбора пароля, ограничение сеансов, восстановление доступа и проверку кода.

## Запуск

```bash
docker compose up --build
```

Интерфейс: <http://localhost:8080>. API напрямую: <http://localhost:3000>.

Учебные учётные записи (роль задаётся сразу, пароль можно сменить):

| Почта | Пароль | Роль |
| --- | --- | --- |
| admin@library.local | Admin123! | Администратор |
| librarian@library.local | Librarian123! | Библиотекарь |
| reader@library.local | Reader123! | Читатель |

Регистрация создаёт только читателя. Администратор меняет роли на странице «Пользователи».

## Роли

- **Читатель** смотрит каталог.
- **Библиотекарь** добавляет и изменяет карточки и обложки.
- **Администратор** делает то же самое, удаляет книги и назначает роли.

Вход выдаёт ключ JWT (HS256) на 30 минут. Ключ подтверждает сеанс. Роль при каждом запросе читается из базы, поэтому смена роли действует сразу. Выход и истечение срока гасят сеанс на сервере.

Одновременно у пользователя не больше 3 сеансов. Четвёртый вход получает `409` и кнопку «Закрыть старый сеанс и войти». Список сеансов открывается кнопкой «Сеансы».

Пять неудачных входов за 15 минут блокируют и адрес, и учётную запись ещё на 15 минут (`429` и заголовок `Retry-After`).

Восстановление пароля: форма «Забыли пароль?». Одноразовая ссылка живёт 30 минут. Пока `MAIL_MODE=log`, письмо пишется в журнал API (`docker compose logs api`) и показывается в интерфейсе. Для настоящего SMTP задайте `MAIL_MODE=smtp`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`. После смены пароля старые сеансы закрываются, а блокировка входа снимается.

Ошибка API всегда выглядит так:

```json
{ "error": "Недостаточно прав", "code": "forbidden", "status": 403, "details": [] }
```

Поля формы перечисляются в `details`.

## Проверка кода

Из корня репозитория:

```bash
npm ci
npm ci --prefix server
npm run check
```

`npm test` в каталоге `server` запускает модульные тесты без базы. `npm run test:integration` ждёт PostgreSQL на `localhost:5432` (его публикует `docker compose`). В GitHub Actions то же самое делает `.github/workflows/ci.yml`: ESLint, модульные тесты и запросы к API.
